Five Consensus Shifts

How the collective position evolved through debate

1
Kill the Word "Clone"
Before
All three reports used "app cloning" terminology liberally
→
After
Unanimous: reposition as "video analysis and specification platform"
"The product should never use the word 'clone.' The positioning is 'video-to-spec' or 'screencast analysis for development.' 'Cloning' implies commoditization and invites dismissal. 'Analysis' implies intelligence and invites premium pricing." — Gemini
2
Parallel Enterprise Track
Before
"Start with developers, expand to enterprise later" (sequential)
→
After
Run two parallel tracks from day one: PLG dev tool AND enterprise legacy modernization
"The biggest strategic error across all three reports is treating 'developer tool' and 'enterprise legacy modernization' as the same product with the same GTM. They are not." — Codex
3
Moat Is Thinner Than Claimed
Before
Each report claimed different defensibility sources
→
After
Honest assessment: moat is thin and temporal. Real defensibility = speed + integrations + data
"The data flywheel is the only real moat, and all three reports underinvest in it. Everything else (integrations, brand, community) is replicable." — Gemini
4
Narration Is the Killer Feature
Before
Video understanding treated as primarily visual
→
After
Audio-visual fusion with narration capture as the most convincing differentiator
"That narration captures intent and business logic that is invisible in the UI. No screenshot tool, no frame extraction approach, and no competitor without native audio processing can replicate this. The narration capability should be the #1 feature in every demo." — Codex
5
Spec Editing Workflow Is Not an Afterthought
Before
Focus solely on generation quality
→
After
Spec correction workflow must be a core MVP feature
"What happens when the spec is wrong? The product needs a spec editing and correction workflow — a way for users to review, annotate, and fix the generated spec before sending it downstream. None of us designed this. It should be a core feature of the MVP." — Claude

The Unresolved Disagreement

The one question the debate could not settle

Specs First

Claude Gemini
  • Phase 1 outputs only specs (PRDs, component inventories, flow diagrams)
  • Avoid competing with Lovable ($6.6B), Bolt ($700M), Cursor ($500M ARR) on code
  • Build integrations to downstream code gen platforms
  • Focus moat on understanding, not generation
"If your Phase 1 product generates React components, you are competing with v0, Lovable, and Bolt on code quality from day one. The whole point of the spec-first approach is to avoid that fight."
— Claude
VS

Code First

Codex
  • Phase 1 should target coders with code output (React/Next.js, Tailwind)
  • Specs don't go viral — working apps do
  • The "wow factor" drives early PLG adoption
  • Risk ceding the viral moment by launching with documents
"A spec document does not go viral. A working app cloned from a 30-second video does. The viral demos that actually get shared on Twitter are working apps generated from a single input."
— Codex
Debate ended 2-to-1 for specs-first, but Codex's viral adoption argument remained unaddressed. The synthesis adopted specs-first while acknowledging the tension.

The Bottom Line

Where three independent analyses converged

Video (unstructured) → Merleau (understanding) → Specs (structured) → Any coding tool (generation)
"Show us any app. We'll write the blueprint."
"Merleau's real opportunity is not building a better screenshot-to-code tool with video input. It is becoming the standard interface between human-demonstrated workflows and the entire AI coding ecosystem — the Figma of video understanding for software development. That requires owning the spec layer, not the code generation layer, and building data assets that compound over time."

— Gemini (final synthesis)
